## Описание проекта

Проект представляет собой RESTful API для управления записями с полноценной системой аутентификации на основе JWT и реализованными мерами защиты от наиболее распространённых уязвимостей из списка **OWASP Top 10**:
- **A03:2021 – Injection** (SQL-инъекции)
- **A07:2021 – Identification and Authentication Failures** (Broken Authentication)
- **A03:2021 – Cross-Site Scripting (XSS)**

Каждый push в репозиторий автоматически проходит проверку статическим анализатором кода (SAST) и анализатором зависимостей (SCA) через GitHub Actions.

## Установка и запуск

### 1. Клонирование репозитория
```bash
git clone https://github.com/programmer1276/secure-api-lab.git
cd secure-api-lab
```

### 2. Создание виртуального окружения
```bash
python3 -m venv venv
source venv/bin/activate  # macOS/Linux
# venv\Scripts\activate   # Windows
```

### 3. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 4. Запуск сервера
```bash
python app.py
```
Сервер запустится на `http://127.0.0.1:5000`. База данных SQLite (`app.db`) будет создана автоматически при первом обращении к API.

## API Документация

### Эндпоинты

| Метод | URL | Описание | Требуется JWT |
|-------|-----|----------|---------------|
| `POST` | `/auth/register` | Регистрация нового пользователя | нет |
| `POST` | `/auth/login` | Аутентификация и получение JWT-токена | нет |
| `GET` | `/api/data` | Получение списка всех записей | да |
| `POST` | `/api/data` | Создание новой записи | да |

### Примеры вызова (curl)

**1. Регистрация пользователя**
```bash
curl -X POST http://127.0.0.1:5000/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username": "testuser", "password": "SecurePass123!"}'
```

**2. Аутентификация (получение JWT)**
```bash
curl -X POST http://127.0.0.1:5000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "testuser", "password": "SecurePass123!"}'
```

**3. Получение данных (с токеном)**
```bash
curl -X GET http://127.0.0.1:5000/api/data \
  -H "Authorization: Bearer <ВАШ_JWT_ТОКЕН>"
```

**4. Добавление данных (с токеном)**
```bash
curl -X POST http://127.0.0.1:5000/api/data \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <ВАШ_JWT_ТОКЕН>" \
  -d '{"title": "Новый пост", "content": "Текст поста"}'
```

## Реализованные меры защиты

### 1. Защита от SQL-инъекций (SQLi) — OWASP A03:2021
**Как реализовано:** Используется ORM **SQLAlchemy**. Все взаимодействия с базой данных происходят через объектную модель. SQLAlchemy автоматически преобразует параметры в **параметризованные запросы (Prepared Statements)**, что полностью исключает возможность конкатенации строк и внедрения произвольного SQL-кода.

### 2. Защита от XSS (Cross-Site Scripting)
**Как реализовано:** Перед возвратом данных клиенту в эндпоинте `GET /api/data` все пользовательские поля (`title`, `content`) проходят через библиотеку **`bleach.clean()`**, которая экранирует потенциально опасные HTML-теги и JavaScript-код (заменяет `<` на `&lt;` и `>` на `&gt;`).

### 3. Защита от Broken Authentication — OWASP A07:2021
- **Хэширование паролей:** Пароли никогда не хранятся в открытом виде. Используется алгоритм **pbkdf2:sha256** с криптографической солью (через `werkzeug.security`), что защищает от атак перебором и радужных таблиц.
- **JWT-аутентификация:** При успешном входе выдаётся JSON Web Token со сроком действия 1 час.
- **Middleware защиты:** Реализован декоратор `@token_required`, который извлекает токен из заголовка `Authorization`, проверяет его HMAC-подпись секретным ключом сервера, валидирует срок действия (`exp`) и наличие пользователя в БД. Любые запросы без валидного токена получают ответ `401 Unauthorized`.

## CI/CD Pipeline и Security-сканеры

В проекте настроен автоматизированный pipeline через **GitHub Actions** (файл `.github/workflows/ci.yml`), который запускается при каждом `push` или `pull request`.

**Этапы pipeline:**
1. **Checkout code** — получение кода из репозитория.
2. **Set up Python** — настройка окружения Python 3.11.
3. **Install dependencies** — установка зависимостей из `requirements.txt`.
4. **SAST Scan (Bandit)** — статический анализ Python-кода на уязвимости.
5. **SCA Scan (OWASP Dependency-Check)** — проверка зависимостей на известные CVE.
6. **Upload Security Reports** — сохранение отчётов как артефактов сборки.

*Примечание:* В процессе настройки Bandit обнаружил уязвимость высокого уровня (B201: `flask_debug_true`). Режим `debug=True` был оперативно заменён на `debug=False` для соответствия стандартам безопасности production-среды, после чего пайплайн успешно прошёл все проверки.
